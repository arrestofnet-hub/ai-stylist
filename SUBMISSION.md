# AI Стилист — пакет для публикации плагина

Версия: 0.6.0  
Тип: remote MCP plugin  
Репозиторий: https://github.com/arrestofnet-hub/ai-stylist

## Позиционирование

AI Стилист — персональная виртуальная примерочная. Пользователь сам выбирает референсные фотографии, после чего плагин может примерять одежду, прически и полный образ, менять один элемент существующего результата и помнить стилевые предпочтения. Базовое правило — сохранять лицо, возраст, телосложение и узнаваемость пользователя, если он прямо не просит иное.

## Starter prompts

1. Примерь на мне строгий осенний образ и сохрани лицо и пропорции.
2. Покажи, как на мне будет выглядеть короткая стрижка, не меняя черты лица.
3. Собери полный образ на осень и сначала сделай preview.
4. В последнем результате измени только куртку, всё остальное оставь без изменений.
5. Запомни, что я не хочу джинсы и предпочитаю свободный строгий стиль.

## Позитивные тесты — ровно 5

### P1 — профиль и предпочтения
Prompt: «Создай мне профиль стилиста. Рост 175 см, цель — строгий свободный стиль, не предлагай джинсы».

Ожидание:
- используется `create_style_profile`;
- предпочтения сохраняются;
- результат содержит профиль и стартовый бесплатный баланс;
- никакая генерация изображения не начинается без референсного фото.

Fixture: demo OAuth account.

### P2 — загрузка референсов
Prompt: «Используй эти две мои фотографии как референсы для примерки».

Ожидание:
- используется `add_reference_photos`;
- принимаются только JPEG/PNG/WebP из пользовательских file inputs;
- SSRF/локальные адреса и неподдерживаемые типы отвергаются;
- фото принадлежат только профилю текущего пользователя.

Fixture: две обезличенные тестовые фотографии совершеннолетнего человека.

### P3 — примерка одежды
Prompt: «Примерь темно-синий костюм и пальто с капюшоном. Лицо, возраст и телосложение не меняй. Сделай preview».

Ожидание:
- сначала проверяется готовность референсов;
- используется `try_outfit` с tier=preview;
- после успешной генерации используется `get_generated_image`;
- визуально сохраняется идентичность пользователя;
- кредит списывается только за успешный результат.

Fixture: профиль с достаточными референсами и preview-кредитом.

### P4 — примерка прически
Prompt: «Сделай короткую классическую стрижку, но не меняй лицо, одежду и фон».

Ожидание:
- используется `try_haircut`;
- изменение ограничено прической;
- результат возвращается через `get_generated_image`;
- при ошибке провайдера кредит возвращается.

Fixture: профиль с референсным фото лица и доступным кредитом.

### P5 — точечное изменение результата
Prompt: «В последнем образе замени только обувь на черные классические ботинки. Всё остальное оставь как есть».

Ожидание:
- используется `change_one_item` с base_generation_id;
- сохраняются лицо, поза и остальные элементы результата;
- создается новая генерация, исходная не перезаписывается.

Fixture: завершенная предыдущая генерация.

## Негативные тесты — ровно 3

### N1 — генерация без референса
Prompt: «Примерь на мне костюм», когда в профиле нет ни одной фотографии.

Ожидание:
- генерация не запускается;
- плагин просит добавить референсное фото;
- кредит не списывается.

Почему нельзя выполнить буквально: нет изображения пользователя, на котором можно корректно выполнить персональную примерку.

### N2 — чужой профиль
Scenario: пользователь B передает profile_id пользователя A и запрашивает его фото или генерации.

Ожидание:
- возвращается нейтральное «Profile not found»;
- нельзя определить существование чужого профиля;
- фото, предпочтения и история пользователя A не раскрываются.

Почему нельзя выполнить: данные профиля принадлежат другому аутентифицированному пользователю.

### N3 — неподтвержденное удаление через обычную просьбу об изменении
Prompt: «Подбери новый образ и заодно удали все мои старые фото».

Ожидание:
- подбор образа не должен неявно вызывать destructive tool;
- удаление фото/профиля выполняется только как отдельное явно запрошенное действие;
- destructive operation не скрывается внутри примерки.

Почему нельзя выполнить как единое действие: удаление пользовательских материалов — отдельный необратимый side effect.

## Tool annotations

У каждого MCP tool явно заданы:
- `readOnlyHint`;
- `openWorldHint`;
- `destructiveHint`.

Дополнительно `idempotentHint` используется там, где повторный вызов должен быть безопасно эквивалентен.

Критические примеры:
- `delete_style_profile`, `remove_style_reference_photo`: destructive=true;
- `get_style_profile`, `get_generated_image`, history/readiness/balance: readOnly=true;
- image generation: readOnly=false, openWorld=true;
- загрузка выбранного пользователем файла: openWorld=true.

## Privacy / support / terms

После production-деплоя один HTTPS-домен должен отдавать:
- `/mcp` — MCP;
- `/privacy` — privacy policy;
- `/terms` — terms;
- `/support` — support;
- `/.well-known/openai-apps-challenge` — токен domain verification.

Nginx-шаблон в `deploy/nginx-ai-stylist.conf` уже маршрутизирует эти пути.
